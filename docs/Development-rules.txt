                  VOID GAMES DEVELOPMENT RULES
══════════════════════════════════════════════════════════════════════

Project Name

Void Games

Version

1.0

Purpose

These rules define the coding standards,
folder architecture, naming conventions,
design consistency, performance standards,
and best practices for the entire project.

These rules MUST be followed for every page,
component, API, database query, and feature.

══════════════════════════════════════════════════════════════════════
GENERAL RULES
══════════════════════════════════════════════════════════════════════

✔ Always write clean code.

✔ Write production-ready code.

✔ Prioritize readability over clever code.

✔ Never duplicate code.

✔ Reuse components whenever possible.

✔ Keep functions small.

✔ Keep components modular.

✔ Separate UI from business logic.

✔ Never hardcode repeated values.

✔ Use constants instead.
