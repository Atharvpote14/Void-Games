AUTHENTICATION
══════════════════════════════════════════════════════════════════════

POST

/auth/google

Purpose

Exchange a Supabase access token for a profile

Request Body

{
    token: "<supabase-access-token>"
}

Note

Google OAuth itself runs client-side via supabase-js
(signInWithOAuth). This endpoint verifies the token with
Supabase Admin and upserts the public.users profile.

----------------------------------------

/auth/user

Purpose

Get current logged-in user (Bearer token required)

----------------------------------------

POST

/auth/logout

Purpose

Logout user (Bearer token required)

📌 One feature I'd add from the beginning

Instead of storing the actual TeraBox URL directly in the frontend, use a redirect API.

Instead of:

User
↓
TeraBox Link

Use:

User
↓
GET /download/redirect/842
↓
Backend checks:
• Link is active?
• Count download
• Log analytics
• Optional Monetag redirect
↓
Redirect to TeraBox

This gives you several advantages:

✅ You can change download links without updating the frontend.
✅ Track download counts accurately.
✅ Disable broken or removed links instantly.
✅ Show multiple mirrors (TeraBox, Pixeldrain, GoFile).
✅ Integrate Monetag or another ad service later without changing the frontend.
